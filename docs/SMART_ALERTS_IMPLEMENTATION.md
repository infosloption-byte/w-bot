# Smart Alerts — separate subscribed feature (implementation milestone 1)

The customer login and owned WhatsApp connections are shared. Translation is still handled only by existing `Group`/`Message`/`processPending`. Smart Alerts has completely separate `AlertSubscription`, `WatchGroup`, `WatchRule`, `WatchEvent`, `AlertMatch`, and `AlertUsage` models, a dedicated ingestion call and its own queue processor. Every API and query must filter by tenant.

**Billing state:** translation uses the existing separate TenantSubscription. Alerts have a separate subscription status and limits, OFF by default, which Platform Admin can grant during a pilot. A user may enable either feature *only while its own subscription is active*. No payment provider is integrated yet, so no public checkout/charge can be claimed. Never enable Smart Alerts automatically for existing translation customers.

**Pilot limits:** admin-configurable monitored groups, rules and alert matches/month. These are *not commercial prices*. Customers can enable/disable alerts, select explicitly consenting groups from their linked WhatsApp account, and configure keyword/tour rules. Inbox alerts are private to the workspace and never posted back to source groups. This first milestone uses a deterministic structured matcher (not a Gemini LLM extractor) and captures optional contact numbers from message text only, so real-world natural-language recall is limited.

**Security:** Baileys is unofficial. There must be authority and informed participant consent for monitoring; monitoring requires explicit per-group opt-in and a connected owned number. No DM monitoring, auto joining, retroactive history scanning, bulk contact export or automatic outreach. Never store linked credentials with alert records. Short retention on message text (cleared after processing); alert records expire after 14 days. No notifications outside the private portal in phase 1. The feature cannot interfere with translation if extraction or matching fails.

**Rollout:** perform full Prisma/client generation and TypeScript build, backend tests and frontend build first; save MySQL backup and Lightsail snapshot. Deploy the API and customer portal together after review (new migration creates new tables and adds translationEnabled with default true). Preserve WhatsApp auth volumes. Run authorized test messages through a dedicated customer connection, with translation on/off permutations, and verify no group replies are produced by Alert pipeline. Validate billing provider and consent compliance before selling.
